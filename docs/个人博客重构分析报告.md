## 二、现有网站分析

### 2.1 技术架构现状

- **框架**：Jekyll + AcadHomepage（学术主页模板，源于 Minimal Mistakes 改造）
- **结构**：单页 About（`_pages/about.md`）+ Blog 时间轴（`_pages/blog.md`）+ 左侧作者侧栏
- **部署**：GitHub Pages

### 2.2 各功能模块评估

| 模块 | 现状 | 问题 |
|------|------|------|
| About Me | 两段英文简介 + 技能清单 | ① 定位模糊：模板是"学术主页"风格（保留了 Google Scholar 爬虫、Publications 注释块），但你的身份是**工程师+技术博主**，学术组件全部闲置；② 简介数据未更新（如社区头衔不全）；③ 纯文字堆砌，无视觉锚点 |
| Technical Skills | 无序列表罗列 | 平铺流水账，AI/云原生等新技能方向未体现；无熟练度/层次区分 |
| Honors and Awards | 按年份列表 | 只有证书文字，无证书图片/徽章/外链验证；社区荣誉（博客之星、专家博主等）与在校奖项混在一起 |
| Educations / Work | 简单列表 | 内容可用，但工作经历只有一句话，无职责/成果描述 |
| 开源项目展示 | **缺失** | GitHub 上 15+ 仓库无任何呈现 |
| 活动展示 | **缺失** | 无"参加 XX 活动担任导师"类时间线 |
| Blog | 时间轴布局已做好 | 仅 2 篇测试文章且**中文乱码**（front-matter 编码问题）；无分类/标签页；与 CSDN 4W 粉丝的内容资产完全脱节 |
| 侧栏社交 | GitHub/CSDN/语雀/Email/Steam | 缺掘金、阿里云、腾讯云、华为云等能佐证影响力的入口 |
| SEO/统计 | Google Analytics、site verification 全部为空 | 无法度量访问，搜索引擎收录差 |

### 2.3 核心矛盾总结

1. **模板气质与个人定位错位**：学术模板 vs 工程师/技术创作者身份
2. **站外影响力与站内呈现严重不对称**：多平台专家头衔、4W 粉丝、15+ 开源项目，网站上几乎看不出来
3. **内容空转**：博客板块形同虚设，没有承接你已有的内容生产能力


### 3.4 图片与媒体最佳实践

1. **目录规范与命名规则**：统一采用 `images/{类别}/{主体}-{内容描述}-{序号/日期}.{格式}`，全小写 + 连字符分隔（kebab-case），禁止中文、空格、下划线混用（URL 安全、跨平台无编码问题）

   ```
   images/
   ├── projects/      # 项目截图：{项目名}-{内容}-{序号}，项目名与 GitHub 仓库名一致
   │   ├── design-patterns-23-cover.webp        # 卡片封面统一叫 cover
   │   ├── design-patterns-23-demo-01.webp      # 详情截图 demo + 两位序号
   │   └── java-handson-lab-demo.gif
   ├── activities/    # 活动照片：{YYYY-MM-DD}-{活动名}-{序号}，自动按时间排序
   │   ├── 2026-05-17-huzhou-demowall-mentor-01.webp
   │   └── 2025-11-08-ascend-meetup-speaker-01.webp
   ├── certs/         # 证书：{年份}-{颁发方}-{证书名}，续期时改年份、旧图留档
   │   ├── 2023-huawei-hccda-ai.webp
   │   └── 2024-aliyun-clouder-openapi.webp
   ├── badges/        # 平台徽章/logo：{平台}-{用途}
   │   ├── csdn-expert.svg
   │   └── aliyun-expert-blogger.svg
   └── site/          # 站点自身资源（favicon、头像等）
       ├── avatar.png
       └── favicon-32x32.png
   ```

   固定语义词：封面 `cover`、演示 `demo`、多图 `-01/-02` 两位序号——写 Markdown 时路径可直接推导，无需翻文件夹
2. **格式与体积**：截图统一 WebP（<200KB），项目动图用 GIF→WebP 或 `<video muted loop>`；证书图片加水印防盗用
3. **尺寸统一**：项目卡片图统一 16:9（如 800×450），活动照片统一比例裁剪，避免布局参差
4. **懒加载**：所有卡片图片加 `loading="lazy"`
5. **点击放大**：模板自带 magnific-popup，证书/活动照片用 lightbox 展示
6. **动态徽章**：数据类展示优先用 shields.io（GitHub stars/followers 自动更新，无需维护图片）
7. **隐私注意**：活动照片避免暴露他人肖像与敏感信息；证书隐去证件号

### 3.5 布局与用户体验改进

- **首屏 Hero**：当前进站直接是文字段落，建议加视觉锚点（头像+定位语+徽章条），移动端优先设计
- **暗色模式**：技术受众普遍偏好，Minimal Mistakes 系模板可通过 skin 变量低成本实现
- **性能**：jQuery 系插件较重，保持现状可接受，但避免再引入新的 jQuery 依赖；开启 `compress_html` 已有配置
- **SEO 补全**（当前全空，成本极低收益高）：
  - 填 `google_analytics_id`、三家 site verification
  - `_config.yml` 的 description 补充中文关键词（Java、AI、昇腾、鲲鹏、物联网）
  - 博客文章 front-matter 补 `excerpt`，站点已装 jekyll-sitemap/feed，收录基础已具备
- **修复编码 Bug**：`_posts/` 下两篇文章中文乱码，需以 UTF-8 (无 BOM) 重存

## 六、二次迭代：信息架构与展示方式重定（对标 rayeren.github.io）

> 背景：第一轮重构已完成数据驱动 + 中英双语，但视觉呈现上还有三个短板：项目无封面图、荣誉证书只有文字列表、活动时间线形式单一；且全站 emoji 密度过高，观感廉价。

### 6.1 原作者页面（rayeren.github.io）的关键观察

1. **单页长滚动，几乎没有 tab**：简介 → News → Publications → Honors → Educations → Talks → Internships 全部在一页内，靠高信息密度取胜——这是学术圈惯例（同行快速扫描成果清单）
2. **视觉签名是论文条目的"左封面图 + 右文字"布局**：会议徽章（NeurIPS 2019）+ 标题 + 作者 + 影响力 bullets，每条都有配图，这是整个页面"不空"的根本原因
3. **emoji 克制**：仅出现在 6 个一级标题上，正文条目零 emoji
4. **News 区短平快**：`日期: 一句话` 纯文字行，承担"最近在干嘛"的时效信号

**对我们的启示**：工程师主页不必照搬单页堆叠（项目/证书是媒体型内容，全塞首页会拖长到失控），但应偷师两点：① "左图右文"条目式项目展示；② 首页放浓缩版全貌 + News，专页放完整内容。

### 6.2 Tab 结论：首页 + 4 个导航页，共 5 页

| 页面 | 定位 | 内容与展示方式 |
| --- | --- | --- |
| **首页 `/`** | 5 秒名片 + 浓缩全貌 | 简介与影响力徽章条 → **最近动态**（自动取 activities 最近 5 条，纯文字日期行）→ **精选项目**（featured 标记的 3-4 个，左封面右文字）→ 技能 → 教育/工作。每段尾部"查看全部 →"链到专页 |
| **Projects** | 全部项目 | 由双列卡片改为 **单列"左封面图 + 右文字"条目式**（对标论文条目）：封面 16:9 约 260px 宽，右侧项目名 + 一句话描述 + 技术标签 + 仓库链接；仍按 AI/学习平台/文档工具分组；无封面时降级为纯文字条目（不用占位图，避免假图充数） |
| **Honors**（新增） | 荣誉证书墙 | 上半：社区荣誉徽章行（可点击验证）；下半：**证书照片墙**——3 列网格缩略图，点击 magnific-popup 灯箱放大（模板自带，零新依赖），图下证书名 + 年份，按年份分组；未扫描的证书以文字行兜底 |
| **Activities** | 日历 + 时间线 | 顶部加**年度日历条**：每年 12 个月份格子，有活动的月份高亮并显示条数，点击平滑滚动到下方时间线对应位置（纯 Liquid 生成 + 几行 JS 锚点，无新库）；下方保留现有时间线，条目可挂活动照片 |
| **Blog** | 技术文章 | 维持现状（时间轴归档） |

**为什么 Honors 值得独立成页**：① 证书照片墙是媒体型内容且会持续增长（10+ 张起步），塞首页严重拖长首屏；② 多平台专家头衔 + 证书是用户最差异化的资产，配得上一个独立入口。
**为什么不再多**：Talks/News 等学术板块内容量不足以成页，分别并入首页动态与 Activities；导航超过 5 项在移动端会折叠，得不偿失。

### 6.3 去 emoji 规范（降"AI 味"）

- 导航项、页面 H1、分组标题、数据文件 title、README 标题：**全部去掉 emoji**
- 分类的视觉区分改用：标题左侧细色条（各页主题色）或模板自带的 Font Awesome 小图标
- 保留例外：无。shields.io 徽章属于数据展示不算 emoji
- 博客正文不强制，但标题同样建议克制

### 6.4 落地清单（按功能拆分提交）

1. 全站去 emoji（页面/导航/数据文件/README）+ 分类标题样式替代
2. Projects 改造为左图右文条目式（projects.yml 已有 image 字段，无需改数据结构）
3. 新增 Honors 页：徽章行 + 证书照片墙（honors.yml 的 awards 条目启用 image 字段）+ lightbox
4. Activities 顶部加年度月份日历条 + 锚点跳转
5. 首页增加"最近动态"与"精选项目"段（projects.yml 加 featured 字段），导航加 Honors 入口
6. 图片补位：项目封面与证书扫描件由用户按 3.4 命名规范放入 images/projects、images/certs 后自动生效
